# 03. 规则系统（Rules）与上下文预算管理

Rules 用于向 Agent 注入强约束（编码规范、禁用 API、安全红线、构建目标目录规范等）。理解它的发现机制与**上下文预算限制**，是保持 Agent 既听话又不“失忆”的关键。

---

## 一、Rules 的存放位置与发现机制

Antigravity 支持两类规则入口：

1. **目录级常驻规则：`GEMINI.md` / `AGENTS.md`**
   - 直接放在任意目录中。
   - Agent 启动或工作时，会从**当前工作目录（CWD）向上回溯至仓库根目录（`.git` 所在目录）**，沿途收集所有祖先目录中的 `GEMINI.md` 与 `AGENTS.md`。
   - 作用域：对其所在目录及所有子目录生效。
   - 格式要求：纯 Markdown，**不支持 YAML Frontmatter**，默认始终激活（Always-on）。
2. **Workspace 与全局规则目录**
   - 项目级：`<project-root>/.agents/rules/*.md` 或 `.agents/rules.json`（也兼容 `.agent/`、`_agents/`、`_agent/`）。
   - 全局级：`~/.gemini/config/`。

---

## 二、去重与防爆上下文机制（关键数值）

Antigravity 对规则加载做了严格的工程保护，编写规则时务必注意以下硬指标：

| 机制 | 限制 / 行为 | 实战建议 |
| :--- | :--- | :--- |
| **自动去重** | 按解析后的真实文件路径去重，同一轮对话中同一规则文件绝不会被重复注入多次 | 放心在多处引用公共规则 |
| **单文件体积上限** | **`24 KB`（24,000 字节）**（在展开 `@[label](path)` 引用之后计算）；超限会按行边界截断 | 单份 `AGENTS.md` 保持精炼，避免塞入大段示例或日志 |
| **全局/常驻规则总预算** | **`20,000` Tokens**（`defaultRulesBudget`），与 Skills / MCP 预算隔离 | 超过预算的规则会从“全文内联”**降级为文件路径指针**，由 Agent 按需读取 |
| **内置插件豁免** | 内置插件附带的规则不计入 20,000 Token 预算，始终全文内联 | 自定义项目规则需自行控制总字数 |

---

## 三、高效编写 Rules 的 4 条黄金法则

1. **常驻规则只放“每次都必须遵守的铁律”**
   - 例如：构建必须走统一脚本、禁止写入某目录、提交代码前必须跑哪些检查。
   - 特定场景才用到的长流程（如发版步骤、某模块排障手册），**不要写进 `AGENTS.md`**，请拆分成 **Skill**（见下一篇），利用渐进式披露按需加载。
2. **明确写出触发条件与正反例**
   - 模糊的“注意代码质量”效果远不如明确的“禁止在 `/home/codes/**/target/` 生成构建产物，必须设置 `CARGO_TARGET_DIR=/data/cargo-target/...`”。
3. **利用层级覆盖做模块化治理**
   - 仓库根目录放全局约束（构建规则、目录约定）。
   - 子服务目录（如 `services/gateway/AGENTS.md`）只放该服务特有的协议与测试命令，只有在该目录下工作时才加载。
4. **长对话及时清理上下文**
   - 当对话中读取了大量文件或输出了长日志时，使用 `/compact` 压缩历史，确保 Rules 和当前任务目标始终处于模型的最佳注意力区间。
