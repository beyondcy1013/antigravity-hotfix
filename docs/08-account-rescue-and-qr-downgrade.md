# 08. 谷歌账号救火：扫码验证降级、RT 失效与设备锁解救

> 本篇整理自一线 Antigravity / Google 账号运维实战经验，聚焦 **RT（Refresh Token）失效、强制扫码验证（QR Code）、“无法验证此设备”** 等高频突发故障的应急救援方案与底层风控原理。

---

## 一、RT 失效与强制扫码验证（QR Code）救火

### 1. 常见触发原因
- 出口 IP 质量过差（机房 IP、被标记为代理/爬虫段的广播 ASN）。
- 短时间内同一 IP 频繁切换多个 Google 账号登录。
- 浏览器指纹存在自动化特征（无头浏览器、WebRTC 泄露、指纹异常）。
- **误操作**：手贱去网页端手动登录并修改 2FA/密码（RT 本质是高敏凭证，频繁手动改动极易触发人机验证导致 RT 失效）。

> [!TIP]
> **登录防踩坑原则**：日常使用 Antigravity 时优先通过工具导入 RT（如开源管理工具 `Antigravity-Manager`），**尽量不要频繁手动网页登录或立即改动 2FA**。

---

### 2. 救火方案 A：冷门节点 + 会话状态机降级（最常用）

**操作步骤：**
1. 在原网络环境下触发登录/扫码验证页面（保留当前浏览器会话，不要关闭标签页）。
2. 开启代理软件（如 Clash）的 **TUN 模式**，将节点切换至**冷门低黑产率地区**（如格陵兰岛、冰岛、列支敦士登等）。
3. 点击页面上的 **“试试其他方式”（Try another way）**；若一次未出现绑定手机/短信选项，可多切换几个冷门节点重试。
4. 成功跳转出手机验证/绑定页面后，绑定一个**未绑定过 Google 的实体手机号**（如 `+86` 实体号或长效实体接码号，**不要用虚拟号**），完成后即可恢复。

**底层风控原理：**
- **人群掩护 vs 独享孤立特征**：冷门共享节点虽然也是 IDC IP，但每天有大量真实用户的 YouTube/Search 正常浏览噪音，会中和登录请求的风险分；反之，只用来登号、没有任何日常网页消费的“独享纯净 VPS”在日志里呈现“100% 登录请求 + 0% 正常浏览”，反而更容易被判为自动化脚本。
- **区域风控基线（Geo-Risk Tier）差异**：99% 的批量扫号集中在美、日、新、港、德等热门地区，风控阈值极高；冷门小众地区自动化攻击预期极低，触发异常时更容易降级为温和的短信验证。
- **市售“双 ISP / 纯净家宽”的 ASN 污染陷阱**：许多标榜静态家宽的 VPS 实为被跨境电商与爬虫买爆的广播 ASN，第三方检测虽显示绿灯，但 Google 内部黑名单已对该 ASN 段直接上最高级扫码验证。
- **状态机合法降级**：同一浏览器会话（携带相同上下文 Token 与指纹）在切换冷门网络后继续点“试试其他方式”，服务端会将其识别为真实用户的网络切换，从而将 `QR_CODE` 降级为 `PHONE_VERIFICATION`。

---

### 3. 救火方案 B：伪装设备降级（iPad Mini 思路）
由于 Antigravity 与 Google Cloud 共用同一套认证体系，当网页端卡死在扫码验证且发短信一直转圈时：
- 可利用社区思路（如 `google-qr-sms-helper`），在 Google Cloud Shell 环境中通过**将设备伪装为 iPad Mini**（系统判定该设备无法使用手机扫码），强制将认证流程降级为向手机发送 **6 位短信验证码**，验证通过后即可连带解锁 Antigravity。
- 若遇到发短信一直转圈提示“这可能需要一些时间”，部分场景将节点临时切换至**香港**或使用手机端 Google App 辅助验证也可恢复（注意操作后切忌继续频繁切 IP）。

## 二、“无法验证此设备”与设备锁解救

当登录报错 **`Could not verify this device`（无法验证此设备）** 或 **`您正在尝试在 Google 无法识别的设备上登录`** 时：

1. **立刻停手！切勿强行重试超过 3 次**
   此时账号处于半保护状态，连续撞库会直接升级为冻结。
2. **冷却与换线**
   更换高质量、低风控值的稳定线路，**等待 30 分钟以上**再重新尝试。
3. **踢出陌生设备报验证怎么办？**
   如果刚接手账号时踢出陌生设备触发验证提示，**不要硬踢**，先保持同一稳定 IP 正常使用 **2 天**，等设备信任度建立后再清理。
4. **手机端登录时机**
   新环境稳定前不建议立刻在手机端登录（手机网络极易跳 IP）；建议桌面端稳定 **48 小时后**再在手机登录，且手机端务必全程开启稳定代理。
